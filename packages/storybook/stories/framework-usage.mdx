# Framework usage

Complete the [Introduction Quick start](?path=/docs/introduction--docs) before using these framework-specific
patterns. Every component is a native custom element; frameworks mainly differ in how they pass arrays, objects,
functions, and custom events.

The examples use the same values throughout:

```ts
const rows = [
  { week: 1, Website: 24, Mobile: 18, Partners: 9 },
  { week: 2, Website: 31, Mobile: 22, Partners: 12 },
];

const series = [{ key: 'Website' }, { key: 'Mobile' }, { key: 'Partners' }];
function formatDomain(value) {
  return `Week ${value}`;
}
function onBarFocus(event) {
  console.log(event.detail);
}
```

String attributes work consistently across frameworks. HTML boolean attributes are presence-based: `stacked`
enables the property, while omitting it disables the property. Writing `stacked="false"` still enables it.

## Lit

Import the component's `define` module once, then use a leading dot for non-string properties and `@` for events.

```ts
import { html } from 'lit';
import '@jsekulowicz/ds-components/bar-chart/define';

html`
  <ds-bar-chart
    title="Weekly activity"
    domain="week"
    x-axis-label="Week"
    y-axis-label="Events"
    stacked
    .data=${rows}
    .series=${series}
    .formatDomain=${formatDomain}
    @ds-bar-focus=${onBarFocus}
  ></ds-bar-chart>
`;
```

Without the dot, an array or object can be coerced to the string `"[object Object]"`.

## React

Install the typed React wrappers in an existing React application:

```sh
pnpm add @jsekulowicz/ds-react
```

```sh
npm install @jsekulowicz/ds-react
```

The wrapper package supports React 18 and newer. Import the theme once as shown in Quick start, then use the wrappers
like regular React components:

```tsx
import { BarChart } from '@jsekulowicz/ds-react';

<BarChart
  title="Weekly activity"
  domain="week"
  xAxisLabel="Week"
  yAxisLabel="Events"
  stacked
  data={rows}
  series={series}
  formatDomain={formatDomain}
  onDsBarFocus={onBarFocus}
/>;
```

- Kebab-case attributes become camelCase props (`x-axis-label` → `xAxisLabel`).
- Custom events use camel-cased `onDs` props (`ds-bar-focus` → `onDsBarFocus`).
- Arrays, objects, and functions pass through as DOM properties.

## Vue 3 with Vite

Custom-element recognition is a template compiler option. Configure it in `vite.config.ts`:

```ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith('ds-'),
        },
      },
    }),
  ],
});
```

Register the component at the application entry point:

```ts
import { createApp } from 'vue';
import '@jsekulowicz/ds-tokens/theme-default.css';
import '@jsekulowicz/ds-components/bar-chart/define';
import App from './App.vue';

createApp(App).mount('#app');
```

Vue chooses DOM properties for declared custom-element properties, so normal bindings work for non-string values:

```html
<template>
  <ds-bar-chart
    title="Weekly activity"
    domain="week"
    x-axis-label="Week"
    y-axis-label="Events"
    stacked
    :data="rows"
    :series="series"
    :format-domain="formatDomain"
    @ds-bar-focus="onBarFocus"
  />
</template>
```

Use Vue's `.prop` binding modifier only when a value must be forced to a DOM property.

## Angular with NgModule

Add `CUSTOM_ELEMENTS_SCHEMA` to the module that owns the consuming template:

```ts
import { CUSTOM_ELEMENTS_SCHEMA, NgModule } from '@angular/core';
import '@jsekulowicz/ds-components/bar-chart/define';

@NgModule({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})
export class ChartsModule {}
```

## Angular standalone component

Standalone components declare the schema in their `@Component` metadata:

```ts
import { Component, CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';
import '@jsekulowicz/ds-components/bar-chart/define';

@Component({
  selector: 'app-chart',
  standalone: true,
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  templateUrl: './chart.component.html',
})
export class ChartComponent {}
```

Both Angular configurations use property and event bindings in the template:

```html
<ds-bar-chart
  title="Weekly activity"
  domain="week"
  x-axis-label="Week"
  y-axis-label="Events"
  stacked
  [data]="rows"
  [series]="series"
  [formatDomain]="formatDomain"
  (ds-bar-focus)="onBarFocus($event)"
></ds-bar-chart>
```

## Plain HTML and JavaScript

Set non-string values as DOM properties after the element exists:

```html
<ds-bar-chart domain="week" x-axis-label="Week" y-axis-label="Events" stacked></ds-bar-chart>

<script type="module">
  import '@jsekulowicz/ds-components/bar-chart/define';

  const rows = [
    { week: 1, Website: 24, Mobile: 18, Partners: 9 },
    { week: 2, Website: 31, Mobile: 22, Partners: 12 },
  ];
  const chart = document.querySelector('ds-bar-chart');
  chart.data = rows;
  chart.series = [{ key: 'Website' }, { key: 'Mobile' }, { key: 'Partners' }];
  chart.formatDomain = (value) => `Week ${value}`;
  chart.addEventListener('ds-bar-focus', (event) => console.log(event.detail));
</script>
```

## Events and types

Custom events bubble and cross shadow boundaries. Their `detail` payload is the same in every framework, and event
types are exported from each component subpath:

```ts
import type { BarChartFocusDetail } from '@jsekulowicz/ds-components/bar-chart';
```
