# Card

Grouped content container. The interactive variant shows a pointer and strengthens its border on hover, to signal that the card leads somewhere; the link or button inside it does the work.

## Anatomy

Slots for `eyebrow`, `title`, default body, `actions` and `footer`. `elevation` and `orientation` control the visual layout; `interactive` gives the whole card a pointer and a hover border.

Three CSS variables size and color the card without reaching into `::part(card)`: `--ds-card-padding`, `--ds-card-gap` and `--ds-card-border-color`. Lower the padding and gap for small tiles in a row, as in the compact tiles example.

    <ds-tab-panel value="guidelines">
      <h3>Do</h3>
      <ul>
        <li>Use cards to group related content that benefits from a clear boundary.</li>
        <li>Pick <code>interactive</code> when the whole card performs one action.</li>
        <li>Keep actions in the <code>actions</code> slot so spacing and responsive alignment stay consistent.</li>
      </ul>
      <h3>Don't</h3>
      <ul>
        <li>Don't nest interactive cards inside another link or control - that traps keyboard users.</li>
        <li>Don't mix many elevations on the same surface; reserve <code>md</code> for the primary focus.</li>
        <li>Don't rely on hover alone to communicate interactivity - keyboard focus must also read as active.</li>
      </ul>
      <h3>Accessibility</h3>
      <ul>
        <li><code>interactive</code> changes only the look: the card itself takes no focus, role or key handling. Place the link or button that performs the card's action first in the card and name it after the title, so keyboard and screen reader users reach the card before any control inside it.</li>
      </ul>
    </ds-tab-panel>
